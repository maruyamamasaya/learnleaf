# POSリプレース案件 PMO事務局支援 業務整理

> 2026年10月8日時点の議事録・説明資料に基づく理解。未確定事項は面談・契約確認で確定する。

## 1. 案件の要点

今回の中心業務は、**AWSインフラ構築そのものではなく、POSシステムリプレース案件のPMO事務局支援**と考えられる。

単純なExcel・PowerPointの更新にとどまらず、テスト進捗や課題を把握し、**次に必要な対応を整理・可視化すること**が期待される。

## 2. 具体的な依頼内容

| 業務 | 具体的な作業 |
| --- | --- |
| PMO支援資料の作成 | 会議資料、テスト計画関連資料の作成・更新 |
| テスト調整状況の更新 | 約40の外部連携先を含めたテスト進捗の集約・可視化 |
| 課題管理 | 課題管理表の更新、対応が必要な課題や遅延の抽出 |
| RAG更新ツール | プロジェクト資料の取り込み・更新を支援するツールの作成・保守 |
| 資料・管理表の改善 | 見やすさ、入力効率、管理方法の改善提案と反映 |

### 役割のポイント

- テスト実施や技術的な不具合修正は、原則として担当の技術者・開発ベンダーが実施する。
- PMO支援側は、予定・実績・遅延原因・影響範囲・担当者・期限を整理する。
- 単なる転記作業ではなく、優先順位の整理、関係者への確認事項の抽出、管理方法の改善まで担う想定。

## 3. プロジェクトの現在地

| 項目 | 状況 |
| --- | --- |
| 対象システム | 百貨店向けPOSシステムのリプレース |
| 対象規模 | 約1,500台 |
| 本番稼働予定 | 2027年9月 |
| 2026年10月時点 | 開発・単体テストが終盤、結合テスト開始直前 |
| これからの重点 | 外部連携テスト、総合テスト、シナリオテストの調整・準備 |
| 外部連携先 | 約40先 |

## 4. 実務のイメージ

### 例：外部結合テストで連携先の環境準備が遅延

**技術担当・開発ベンダー側**

- 接続設定や環境を確認する。
- 不具合調査・修正、技術的な対応を行う。

**今回のPMO支援側**

1. 対象のテストと実施予定日を把握する。
2. 遅延理由・対応状況を確認する。
3. 後続テストへの影響範囲を整理する。
4. 対応担当者と期限を明確にする。
5. 課題管理表、進捗資料、会議資料へ反映する。
6. 必要に応じてテスト順序や管理方法の改善を提案する。

つまり、**テストを直接行うより、テストが計画どおり進むように支援する仕事**が中心。

## 5. POS案件と横断的なAWS技術支援の切り分け

現状の資料からは、少なくとも次の2系統の業務が存在すると理解している。

| 区分 | 主な作業 | 位置づけ |
| --- | --- | --- |
| POS案件のPMO支援 | テスト調整、進捗・課題管理、資料作成・改善、RAG更新ツール | 今回の明示的な主業務 |
| 横断的な技術サポート | AWS環境整備、技術相談、ツール作成、将来的なアプリ支援 | 今後立ち上げたい複数案件向けの支援業務を含む可能性 |

**注意：** AWS環境整備が今回の1人月の業務にどれだけ含まれるかは未確定。議事録に登場した内容を、すべて今回のPOS支援の必須業務とみなさない。

## 6. 関係者と指示系統

説明資料上は、顧客との打ち合わせ・やり取りを原則**B社**が担当し、**C社**はB社から直接指示を受ける想定。

```text
顧客
  │ 対外調整・打ち合わせ
  ▼
B社（顧客側PMO・窓口）
  │ 業務指示・依頼
  ▼
C社（今回の支援チーム）
  ├─ PMO資料作成・改善
  ├─ テスト進捗・課題管理
  └─ RAG更新ツール支援
```

※ 図は現時点の理解を簡略化したもの。実際の契約上の指揮命令系統、顧客との接点、責任分界は別途確認する。

## 7. 面談前に確認したいこと

### 最優先：1人月の稼働配分

- POSのPMO事務局支援が全体の何割を占めるか。
- AWS環境整備の対応が今回の稼働に含まれるか。
- RAG更新ツールの新規開発・保守に必要な工数はどれくらいか。
- 複数案件の兼務がある場合、優先順位や工数配分を誰が決めるか。

### 業務範囲・成果物

- 課題の整理・提案までか、改善策の実施管理まで担うか。
- テスト計画への関与範囲（資料化のみか、計画調整までか）。
- RAG更新ツールの技術構成、既存資産、開発責任、保守範囲。
- 成果物のレビュー・承認者、利用する管理ツール、会議体、更新頻度。

### 契約・指揮命令・勤怠

- 「人月の派遣契約」という説明と、実際の契約形態・指揮命令系統の整合。
- B社からの直接指示の範囲と、C社の管理責任者の役割。
- 複数案件の稼働時間の記録・按分・精算方法。
- 顧客と直接調整する必要が生じた場合の窓口・承認ルール。

※ 契約形態の適否はこのメモでは判断しない。会社側の契約・法務・労務担当に確認する。

## 8. 現時点での理解（まとめ）

**今回の中心的な価値は、約1,500台規模のPOSリプレースを対象に、約40の外部連携先も含めたテスト進捗と課題を整理し、プロジェクトを前進させるための次の対応を見える化すること。**

AWSの技術サポートやRAGツール開発は関連するが、担当比率・責任範囲は面談で要確認。
